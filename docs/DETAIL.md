# 待办事项 · Todo Queue

模型正在干活的时候，把**下一段提示词**先排好队。这一轮结束时，队列里第一条会自动接着发出去开始新事项——可以留在同一个会话里继续，也可以每条都新开一个会话。

## 安装

在 DSH 的「插件」页点「+ 添加插件」选择本目录；或命令行 `dsh plugin add github:omnijk/dsh-todolist`。安装后侧边栏出现「待办事项」入口，点开就是一个完整的主面板页面。

## 它解决什么

一次会话里，人往往要等模型跑完才能写下一句。等的那几分钟里思路最清楚，却没法输入。
这个面板把「想好的下一件事」先存起来，按顺序排好，模型一空闲就自动交出去，中间不用你回来点发送。

## 怎么用

1. 侧边栏点「待办事项」打开面板。
2. 在输入框写下要交给 AI 的完整事项（背景、要求、注意点都可以写），点「添加待办」或 `Ctrl / ⌘ + Enter`。
3. 打开开关 **自动续跑**。开关下面会显示「续跑范围：<工作区>」，说明这条队列跟着哪个项目走。
4. 「续跑位置」选择：
   - **同一会话**：接着刚刚结束的那一轮继续发（最常用）。
   - **新建会话**：每条待办都开一个新会话，适合互不相干的任务。
5. 回到会话继续工作。这个工作区里任意会话结束一轮后，队列第一条自动发送。
6. 关掉开关就完全手动：只有点「▶ 开始」才会发。

队列是按**工作区（项目）**算的：你在哪个工作区的会话里，面板就显示那个工作区的队列。切到别的项目会看到它自己的队列，切回来原样还在。

行内操作（鼠标悬停出现）：

| 操作 | 作用 |
| --- | --- |
| ▶ 开始 | 立刻把这条发出去，不必等 |
| 💬 填入对话 | 只填进输入框、不发送，留给你改完再按回车 |
| ✓ 标记完成 / ↺ 恢复待办 | 手动把一条划掉或放回队列 |
| 拖动 | 按住左侧手柄上下拖，调整先后顺序 |
| ✎ | 就地修改内容（`Ctrl / ⌘ + Enter` 保存，`Esc` 取消） |
| 🗑 | 删除 |

双击标题也能直接编辑。列表底部会统计已完成条数，可以一键「清除已完成」。

写了一半还没点「添加待办」的文字也不会丢：切会话、切面板、甚至刷新页面，回到面板时它还在（按工作区分别记住）。这跟飞书/钉钉文档的「自动保存草稿」是一个意思——只有主动清空或添加成待办才会消失。

## 后台行为不会打扰你

自动续跑在后台发出提示词时**不会**切换页面、不会跳进会话、不会抢焦点：它只是把提示词塞进那个会话的队列里。只有你自己点「▶ 开始」或「💬 填入对话」时才会跳到会话。

## 数据放在哪

待办的正文由插件 Host 半写入当前 DSH profile：

```
<profile>/plugin-data/dsh-todolist/state.json
```

浏览器端通过同一个 origin 的 `/api/todolist.state`（GET 读取 / POST 保存）访问它，因此换端口、重启 GUI 都不会丢数据。数据按**工作区**分开存放，切换工作区就看到各自的队列。

## 注意点

- 自动续跑只在这个工作区里触发，别的工作区的会话结束不会牵动这里的队列。
- 子代理的会话结束不会触发队列。
- 发送成功后这条自动标记为已完成；失败时（例如会话已被关闭）面板会提示原因，这条留在队列里，不会丢。
- 队列、开关、续跑位置、草稿都会立即保存，不需要手动保存。

## 队列的可靠性

- 一条待办被发出去之前，会先把它标记为已完成并写入磁盘，然后才发送；发送失败会回滚成待办状态并提示原因。这样即使发送过程中又有新的一轮结束，也不会把同一条重复发第二次。
- 打开「待办事项」面板、以及从别的窗口切回来时，面板会重新从磁盘同步一次，避免旧数据覆盖别处新增的待办。
- 排队中的草稿、开关、顺序都会随改动即时保存（约 0.2 秒防抖）。
